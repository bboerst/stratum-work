## Optional scheduling, lifecycle and Secret references

`topologySpreadConstraints` renders into the pod spec and supports Helm templates
in its values, so selectors can use `stratum-work-webapp.fullname`. Use the
existing `app` selector label, not an assumed instance label.

`podDisruptionBudget.enabled` adds a release-scoped policy/v1 PDB with
`podDisruptionBudget.maxUnavailable`. Deployment rollout settings remain under
`updateStrategy`; a PDB does not control rollouts or OOM eviction.

`readinessProbe` and `startupProbe` are optional pod-container probe objects.
`terminationGracePeriodSeconds` defaults to the previous 10 seconds. No probe or
spread constraint is enabled by default. The temporary volume remains disk-backed.

Put non-secret environment values in `env`. Put credential references in
`envValueFrom`, for example:

```yaml
envValueFrom:
  DATABASE_URL:
    secretKeyRef:
      name: application-env
      key: DATABASE_URL
```

The chart fails if a key exists in both maps. There is no default database
credential; releases must supply an explicit value or Secret reference.

The infrastructure repository's `scripts/validate-cluster-stability.py` renders
public/dev/hidden releases, compares existing routing behavior and checks these
settings against the actual manifests. Public uses Flux Revision reconciliation
so these changes do not require a chart version bump affecting other releases.
